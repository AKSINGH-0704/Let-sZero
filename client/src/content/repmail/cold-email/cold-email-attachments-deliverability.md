For a first cold email, **do not attach a file unless the recipient has a clear reason to expect it**. Put the essential point in the message, use a relevant link when the reader needs more context, or ask permission before sharing a tailored document. Removing an attachment can reduce friction, but it does not guarantee delivery or inbox placement.

## Why attachments change the decision

A file creates extra work: the recipient must assess whether it is safe, download it, find a viewer, and decide whether it is relevant. Receivers and security systems may also inspect files differently from plain message content. Those mechanisms vary, so avoid claims that a PDF, image, or document is universally safe or universally filtered.

The copy question comes first: does the recipient need this file to understand your request? If the answer is no, the attachment is probably serving the sender’s convenience. Replace it with one concrete proof point and a link to a focused page. If the document is useful only after a conversation, write “I can send the brief if useful” and let the recipient choose.

## Use a format decision, not a blanket rule

An attachment can be reasonable in a known workflow, an expected exchange, or a reply where the recipient asked for it. It is harder to justify when it is a generic deck, a large portfolio, or an unrequested file in the first touch. A link is not automatically harmless: it still needs a trustworthy destination, a clear label, and a reason to click. Keep the email useful even if the link is never opened.

The [plain-text versus HTML email guide](/repmail/learn/deliverability/plain-text-vs-html-email) explains the surrounding message-format trade-offs. For reusable structures, adapt the [cold email templates](/repmail/learn/cold-email/cold-email-templates), but preserve the recipient-specific reason instead of adding a standard brochure.

## Safer attachment workflow

1. **Name the job.** Write down the decision the file helps the recipient make.
2. **Reduce the payload.** Put the one necessary fact in the email and remove unrelated pages or data.
3. **Check expectation.** If the recipient did not request it, use a permission question or a link with context.
4. **Make the fallback explicit.** Ensure the email still contains the relevance, proof, and next step without the file.
5. **Review the send.** Check destination, access settings, filename, message rendering, and suppression before sending.

Do not use “no attachment” as a proxy for deliverability testing. Run the [pre-send deliverability checklist](/repmail/learn/deliverability/pre-send-deliverability-checklist) and evaluate authentication, list quality, message content, and measurement together. There is no supplied measurement proving that one attachment format or removal rule produces a universal placement outcome.
